# Main storefront: final single-slider architecture

This supersedes the earlier two-slider design. The second website repository is unrelated and unchanged.

## Source and routes

- Shared customer shell: `legacy/store.html`, `public/app.js`, `public/style.css`, `public/i18n.js`.
- `/`: hero → one product slider (max ten) → campaign → three journal categories → footer. Header retains the established sidebar/compact mobile menu.
- `/shop`: own server route, four-column desktop/two-column mobile grid, all published persisted products without the homepage cap, category/search/sort.
- `/products/[slug]`: own server route, server 404 for unknown/hidden products; existing stock/variant cart behavior plus quantity input.
- `/shop?category=OUTER`, `/shop?category=TSHIRT`, `/shop?category=BOTTOMS`: category pages. KNITWEAR and HOODIES are distinct categories, never used to fill T-SHIRT. Generic tank/long-sleeve products remain TOPS.
- Old homepage category and product query URLs redirect to the corresponding new route.
- `/api/admin/catalog-import` POST: existing server owner/origin guard, bounded input, revision compare-and-set, additive idempotent import of the supplied nine products.
- `/admin/preview` POST: server owner/origin guard, schema-validated bounded content; returns a no-store/noindex preview of unsaved content. Does not write data or reuse the real cart.

Vercel `deploy/vercel/app`, `lib`, `public` are generated by `scripts/prepare.mjs`; edit source, never generated output. The generator now also copies `lib/catalog-import.ts`.

## Product import

The provided `옷.zip` contains nine exact English filenames. `lib/catalog-import.ts` is an import manifest, not the runtime catalogue source. Public catalogue and individual detail pages always use existing persisted store_content via `readStore`.

Original PNG bytes are stored under `public/assets/clothes-*.png`; `docs/supplied-products.json` records filenames, IDs, lengths and SHA-256 hashes. All nine are 1122×1402. Supplied proposed KRW prices are editable. Existing products, edits, visibility, customer/order/inventory records remain untouched by import. Stable product IDs prevent repeated inserts. Import checks the store revision, preserves existing records, and fails on concurrent saves or the existing 100-product content limit.

Use the authenticated admin **제공된 9개 상품 가져오기** button. Save or discard pending edits first. It writes only store_content; the response reports added/skipped IDs. Applying again preserves names/prices/visibility and makes no write if all nine already exist.

No sizes, materials, measurements or stock are invented. New records have `sizes: []`, so they display but cannot be purchased. Enter actual options under homepage management, then set actual stock and enable sales under order/inventory management. Both customer checkout and the stock API reject made-up options. Existing site test-order closure stays in place.

The shared `public/journal-presets.js` fills missing/empty journal images at render time, independently of product import: operator-supplied jacket/denim model images and the supplied blue layered tee image. Existing configured images are preserved, and the legacy middle TOPS assignment maps to TSHIRT. Customer rendering makes no database writes. The editor uses the same effective defaults; its reset action restores the default image. These are not newly commissioned editorial images.

## Homepage behavior

Hero changes every 4000ms with 400ms fades; hover, focused keyboard interaction, manual navigation/touch, visibility and reduced motion pause it. Hero clicks always navigate to `/shop`; old saved per-banner href values are retained for data compatibility but are no longer used. Separate mobile banner uploads and ordering remain available.

One nonwrapping horizontal rail: desktop thirds, mobile halves, zero gaps, subtle 1px separators; mouse drag/native touch swipe and arrow-key navigation. English product name, price, QUICK ADD + appear at the bottom on hover/focus without changing image geometry. Touch devices show accessible controls. Image clicks navigate to individual pages; QUICK ADD opens the existing option selector/cart. No second rail is rendered or managed; old slider02 JSON remains optional for compatibility.

Campaign is a single intrinsic-aspect-ratio image with optional mobile source and no shopping overlays. The supplied ZIP now provides the exact 1536×1024 PNG at `/assets/editorial-brutalist-monochrome.png` (original bytes, SHA-256 in `docs/campaign-asset.json`). Shared media presets apply it when campaign settings have no image, without a database write. Saved custom images/mobile variants take precedence. `campaign.enabled: false` explicitly hides it, including across save/reload; removing the PC image sets that flag and uploading a replacement enables it. Existing null-image settings inherit the newly supplied artwork.

Administrator brand and product language selectors now default to Korean (`ko`), including the static HTML initial option. Other translation languages and saved translations remain available; customer-facing product names remain English.

## Banner exchange, seasonal journal captions and contrast

The requested first hero/campaign exchange is applied by shared `StoreCampaign.layout` only to the known previous pairing (first banner `campaign-wide.png`, campaign default `editorial-brutalist-monochrome.png`). It exchanges the first banner and campaign while keeping the other banner. Desktop/mobile sources move together. `homepage.mediaLayout: swapped-v1` makes the transformation idempotent; saving in the authenticated editor persists the effective layout. Other custom pairings are preserved. This does not write to production during page reads.

Journal category labels are overlaid at bottom right: bold category title above a thin `WINTER BEST` seasonal line. `homepage.journalSeason` is editable (up to 40 characters); each journal entry can override `title` (30 characters) and `textTone` (`auto`, `light`, `dark`). `homepage.heroTextTone` offers the same automatic/manual choice. Existing content remains valid without the new optional fields.

Automatic contrast samples the displayed image region in a small canvas and chooses black/white by relative luminance. It updates on hero image changes, journal image load and responsive resize. Tainted cross-origin images use CSS difference blending; administrators can force white or black. No CORS or authentication protection is weakened.
