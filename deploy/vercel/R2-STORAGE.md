# Vercel에서 기존 R2 이미지를 연결하는 방법

이 폴더의 서버는 Cloudflare Workers의 `BUCKET` 바인딩을 그대로 사용할 수 없습니다. **기존 Sites 관리 버킷에 대표님이 S3 접근 권한을 발급받을 수 있다고 가정하면 안 됩니다.** 접근 권한을 실제로 확인한 경우에만 그 버킷을 서버 전용 S3 자격증명으로 연결합니다. 접근할 수 없다면 Sites에서 원본 이미지 내보내기를 받은 뒤, 대표님이 관리하는 새 비공개 R2 버킷으로 같은 UUID 파일명을 유지해서 이전해야 합니다. 현재 도구에서는 기존 Sites 버킷의 이미지 내보내기를 실행하지 못했습니다.

## Vercel 환경변수

- `R2_ACCOUNT_ID`: R2 버킷이 있는 Cloudflare 계정 ID
- `R2_BUCKET_NAME`: 접근 권한이 확인된 기존 버킷 또는 이전용 새 비공개 버킷 이름
- `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`: 해당 버킷에만 필요한 읽기·쓰기 권한을 가진 서버 전용 R2 자격증명
- `UPLOAD_SIGNING_SECRET`: 32바이트 이상 길이의 독립적인 무작위 비밀값. 예를 들어 로컬에서 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`로 생성한 값을 Vercel 환경변수에 직접 저장합니다.

이 값들은 `NEXT_PUBLIC_` 이름을 사용하지 않으며 브라우저 코드·Git·채팅에 넣지 않습니다. Vercel 운영 환경과 미리보기 환경을 구분해서 설정합니다. 검증용 배포에는 별도의 테스트 버킷과 테스트 DB를 사용합니다. 이 소스가 자격증명을 자동으로 발급하거나 버킷을 공개로 변경하지 않습니다.

## 기존 Sites 버킷에 접근할 수 없는 경우

Sites 원본 이미지 내보내기에서 업로드된 UUID 파일들을 한 폴더에 모읍니다. 사이트에 함께 들어 있는 `public/assets` 시안 이미지는 GitHub 소스에 포함되어 있어 이 작업의 대상이 아닙니다.

```bash
node scripts/import-images.mjs --source /절대경로/내보낸-이미지
```

위 명령은 연결 정보 없이 로컬 파일명·형식·8MB 제한을 검증만 합니다. 파일 이름을 변경하거나 이미지 저장소에 쓰지 않습니다. 실제 이전은 새 비공개 대상 버킷의 환경변수를 로컬 보안 환경에 설정하고 다음 명령을 실행합니다.

```bash
node scripts/import-images.mjs --source /절대경로/내보낸-이미지 --apply
```

이전 도구는 모든 파일을 먼저 검증하고, 모든 대상 이름이 비어 있는지 확인한 뒤, `If-None-Match: *` 조건으로 업로드합니다. 같은 이름이 이미 존재하거나 업로드 중 충돌하면 중단하며 기존 파일을 덮어쓰거나 삭제하지 않습니다. 일부 업로드 후 실패하면 완료된 파일이 남습니다. 재시도 전에 결과를 확인해야 합니다. 현재는 실제 운영 이미지 이전을 실행하지 않았습니다.

## 업로드 허용 주소(CORS)

R2 버킷 설정에서 실제 운영 도메인과 승인한 Vercel 미리보기 주소만 허용합니다. 다음 예시의 주소를 실제 배포 주소로 바꿉니다. `*`로 모든 주소를 허용할 필요는 없습니다.

```json
[
  {
    "AllowedOrigins": ["https://실제-운영-주소.vercel.app"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type"],
    "MaxAgeSeconds": 3600
  }
]
```

이미지는 Vercel 서버를 거치지 않고 브라우저에서 R2로 직접 전송되므로 이 설정이 없으면 관리자 업로드가 실패합니다. 읽기는 기존 `/media/<파일명>` 주소에서 60초짜리 읽기 전용 서명 주소로 이동합니다. 이미지 표시를 위해 버킷을 공개로 만들 필요가 없습니다.

## 업로드 처리와 제한

1. 서버가 로그인한 관리자와 요청 출처를 확인합니다.
2. JPG·PNG·WebP와 8MB 이하 크기만 허용합니다. 10분짜리 업로드 주소와 본인에게만 유효한 확인 토큰을 발급합니다.
3. 브라우저는 서명된 파일 크기와 형식으로 R2의 `_uploads/` 임시 경로에 전송합니다. 이 경로는 `/media/`에서 읽을 수 없습니다.
4. 서버가 다시 관리자와 출처를 확인하고 DB의 일회용 기록을 확보합니다. 실제 파일의 바이트 수·MIME·JPG/PNG/WebP 식별 바이트를 검증합니다.
5. 검증한 바이트를 새 UUID 파일명으로 저장하고 `/media/<UUID>.<확장자>` 주소를 반환합니다. 임시 파일은 삭제합니다.

파일 자체를 Vercel 함수로 보내거나 Vercel 응답으로 돌려주지 않으므로 4.5MB 함수 요청·응답 제한을 피하면서 기존 8MB 이미지 제한을 유지합니다. 실제 R2·Vercel 연결은 계정 설정 후 별도로 검증해야 합니다.

## 임시 파일 정리

업로드 중 창을 닫거나 네트워크가 끊기면 임시 파일이 남을 수 있습니다. R2에서 `_uploads/` 접두어에만 적용하는 객체 수명 주기를 설정해, 예를 들어 하루 뒤 임시 파일을 삭제하도록 구성합니다. 완료된 UUID 이미지를 이 규칙에 포함하면 안 됩니다. 수명 주기나 자동 백업은 이 소스가 실제로 설정하지 않습니다.

DB의 `store_upload_tickets`는 인증 확인·중복 처리 방지를 위한 기록입니다. 보존 기간과 운영 기록 정리 정책은 운영자가 따로 정해야 합니다. 회원·주문·기존 이미지를 삭제하거나 덮어쓰는 마이그레이션은 포함하지 않습니다.
