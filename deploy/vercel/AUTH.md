# Vercel 이메일 로그인 설정

이 배포본은 Clerk의 검증된 세션을 사용합니다. 기존 Sites의 ChatGPT 로그인 헤더는 읽지 않습니다. 쇼핑몰 비밀번호를 자체 저장하거나 이메일 주소만으로 기존 회원을 연결하지 않습니다.

## 운영자가 연결할 항목

1. Clerk에서 이 쇼핑몰용 애플리케이션을 만듭니다. 이메일 주소와 비밀번호 가입을 켜고, **가입 중 이메일 인증을 필수**로 설정합니다. 이메일을 기본 식별자로 사용합니다. 카카오·네이버 또는 다른 로그인은 별도로 실제 연결하기 전까지 활성화하지 않습니다.
2. Clerk 운영 인스턴스를 실제 Vercel 도메인에 연결합니다. Clerk에서 요구하는 도메인/DNS와 이메일 발송 설정을 완료합니다. 테스트 키로 실제 판매를 시작하지 않습니다.
3. Vercel 환경변수에 `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `NEXT_PUBLIC_SITE_URL`을 등록합니다. 마지막 값은 실제 홈페이지의 HTTPS 주소이며 경로·쿼리·인증정보 없이 입력합니다. 비밀키는 Vercel의 비밀 환경변수에만 저장합니다. 채팅·Git·화면에 공개하지 않습니다.
4. Turso 데이터베이스 연결과 마이그레이션을 완료합니다. 처음 만든 빈 DB는 [시작 안내](START-HERE.md)에 따라 인증된 대표님 계정으로 `/setup`의 **새 DB 준비** 버튼을 사용할 수 있습니다. 인증된 계정이 정확히 `/setup`으로 돌아가는 경우만 초기 테이블 없이 이동할 수 있습니다. 회원·관리자 화면에는 DB와 회원 ID 연결표 검사를 유지합니다.
5. 로그인 화면에서 이메일 인증 코드 발송·수신, 올바른/잘못된 비밀번호, 비밀번호 재설정 메일과 재설정 완료, 새 기기의 로그인, 로그아웃을 실제 운영 도메인에서 확인합니다. 이 저장소의 모의 테스트는 실제 발송·실제 계정 검증을 대신하지 않습니다.

비밀번호 정책, 세션 만료·기기 관리, 이메일 코드·재설정 토큰 발급과 발송은 Clerk가 처리합니다. 이 프로젝트는 가입 후 다시 Clerk 서버에서 확인한 **인증된 기본 이메일**과 실제 세션 사용자 ID만 사용합니다. 기본 이메일이 미인증이면 `/auth/verify-email`의 계정 관리 화면에서 인증을 마쳐야 합니다.

## 고객의 이용 순서

- `/signup` 또는 홈페이지의 로그인 / 회원가입으로 진입합니다.
- `/auth/sign-in`에서 이메일로 로그인하거나 `/auth/sign-up`에서 이메일 계정을 만듭니다. 인증 코드를 확인합니다.
- 쇼핑몰의 `/signup`에서 이름을 입력하고 실제 이용약관·개인정보 안내에 동의합니다.
- 기존 회원은 `/account`로, 주문 진행 중이면 주문서로 돌아갑니다.

Clerk 계정 생성과 쇼핑몰의 약관 동의·회원 등록은 별개입니다. 실제 운영 모드에서는 확인한 이용약관·개인정보 안내가 비어 있으면 쇼핑몰 가입을 차단합니다. 대표님이 지정한 현재 테스트 모드의 시험용 안내와 실제 주문 중지 조건은 [테스트 사이트 안내](TEST-SITE.md)에 설명합니다.

## 기존 회원과 관리자

새 Clerk 사용자는 `clerk:<provider user ID>`라는 새 내부 ID를 사용합니다. 기존 회원·주문을 옮기는 경우, 확인한 신원 쌍을 별도의 `db:link` 도구로 명시적으로 연결합니다. `auth_identity_links`에는 provider user ID, 기존 Sites user ID, 확인 시각이 저장됩니다.

실행 중 이메일이 같다는 이유로 기존 ID를 자동 연결하지 않습니다. 연결표는 조회만 하며, 기존 `store_owner` 관리자 ID도 삭제하거나 초기화하지 않습니다. 관리자 이메일을 사용하는 다른 계정이라도 연결한 provider ID가 아니면 기존 관리자 권한을 얻지 못합니다. 기존 회원·주문 데이터를 가져온 뒤 신원 연결까지 완료해야 같은 고객이 이전 내역을 볼 수 있습니다.

## 경로와 출처 보호

- `/auth/sign-in?next=...`, `/auth/sign-up?next=...`에는 안전한 내부 경로만 허용합니다. 외부 주소·역슬래시·제어문자·인증 경로 반복은 홈페이지로 대체합니다.
- `/auth/sign-out?next=...`의 GET은 확인 화면입니다. 실제 로그아웃은 같은 출처의 POST로만 처리하고 Clerk 세션을 폐기합니다.
- 운영 세션의 허용 출처는 `NEXT_PUBLIC_SITE_URL`입니다. Vercel 미리보기는 `VERCEL_ENV=preview`일 때 플랫폼이 제공한 `VERCEL_URL`을 추가로 허용합니다. 임의 Host 헤더에서 신뢰할 주소를 만들지 않습니다.
- 설정 누락 시 인증 경로는 503 ‘로그인 연결 준비 중’입니다. 로컬 개발의 HTTP 주소는 비운영 환경의 localhost/127.0.0.1/::1만 허용합니다.

## 로그인 연결 문제 확인

`/setup`에서 사이트 주소·공개키·비밀키별로 누락, 형식 오류, 설정 확인 상태를 볼 수 있습니다. 값이나 대표님 이메일을 표시하지 않습니다. 형식이 맞더라도 같은 Clerk 앱의 실제 키인지, 이메일 발송·세션이 작동하는지는 실제 로그인으로 확인해야 합니다. Vercel 값 칸에는 키 전체만 입력하고 `이름=` 부분, 따옴표 또는 여러 줄을 넣지 않습니다. 테스트용 사이트는 같은 Development 인스턴스의 공개키·비밀키를 사용합니다.

이전에 입력된 `NEXT_PUBLIC_CLERK_PUBLISHABLE`은 정식 이름 `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`가 아예 없을 때만 호환 이름으로 읽습니다. 정식 이름에 빈 값이나 잘못된 값이 있어도 다른 키로 바꾸지 않습니다. 비밀키의 호환 이름이나 인증 우회는 추가하지 않습니다. 수정한 Vercel 환경변수는 재배포 후 적용됩니다.

Clerk에서 이메일 인증과 로그인을 마쳤지만 쇼핑몰 DB의 계정 연결 정보를 읽지 못하면 로그인 상태와 원래 목적지를 유지한 재시도 화면을 표시합니다. 고객을 `/setup`으로 강제 이동하지 않습니다. 명시적으로 `/setup`을 목적지로 선택한 경우만 그 화면으로 이동합니다. 수동 새 빈 DB 준비는 대표님의 확인된 로그인 이메일과 관리자 설정이 일치해야 실행되며, 성공하면 `/signup`으로 이어집니다. 공개 확인 화면 방문만으로 관리자·회원 권한을 주거나 테이블을 만들지 않습니다. 새 배너 업로드에는 별도의 R2 연결이 필요합니다.

대표님이 기존 회원·주문 없는 테스트 DB의 준비를 위임한 현재 배포는 `scripts/provision.mjs`를 먼저 실행합니다. 확정된 사이트 주소의 Vercel Production 빌드이면서 명시적 테스트 모드일 때만 서버에 저장된 연결값을 사용합니다. 빈 DB만 초기화하고 동일한 마이그레이션 이력은 검증 후 재사용합니다. 기존 관리자는 보존합니다. 관리자가 없는 DB는 모든 앱 자료가 비어 있어야 하며, `OWNER_BOOTSTRAP_EMAIL`과 정확히 일치하는 Clerk 기본 이메일·인증·실제 로그인 이력·정상 계정을 확인한 기존 사용자 한 명만 관리자 ID로 기록할 수 있습니다. 계정 생성·비밀번호 발급·이메일 인증 생략은 하지 않습니다. 조건을 충족하는 계정이 없으면 DB 준비만 마치고 기존 로그인 후 관리자 등록 절차를 유지합니다. 로컬·Preview·다른 사이트·실제 운영 모드에서는 자동 작업을 하지 않습니다.

대시보드에서 끈 가입 필드를 사이트가 계속 요구하면 연결된 환경부터 확인합니다. 명시적 테스트 모드의 `GET /api/setup/auth-environment`는 서버 비밀키로 Clerk의 인스턴스·도메인 정보만 읽어 공개 식별자인 환경 ID, 환경 종류, 공개키·비밀키가 같은 Frontend API를 가리키는지 반환합니다. 키값·회원·세션·관리자·DB 자료는 반환하거나 변경하지 않으며, 같은 서버에서 안전한 결과를 1분 동안 재사용합니다. 실제 운영 모드나 설정 누락·공급자 오류에서는 조회를 차단합니다. 대시보드 주소의 `instances/ins_…`와 비교하여 같은 환경인지 확인한 뒤 설정을 변경합니다. 설정이 같다는 확인 없이 이전 가입 상태를 원인으로 단정하거나 필수 입력을 화면에서만 숨기지 않습니다.

## 검증 범위

`node deploy/vercel/tests/auth.cjs`는 Clerk SDK를 모의 처리하고 분리된 SQLite를 사용합니다. 가짜 Sites 헤더 거부, 기본 이메일 인증 확인, 계정/회원 ID 연결, 기존 관리자 ID 유지, 안전한 이동 경로, 출처 제한과 로그아웃 보호를 확인합니다. 실제 Clerk 운영 계정 로그인·이메일 발송·재설정·생산 세션 동작은 외부 계정 연결 후 별도로 확인해야 합니다.
